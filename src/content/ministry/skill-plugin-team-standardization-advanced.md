> 대상: 비개발 파워유저. **코딩 없이** 마크다운만으로 나만의 스킬을 만듭니다.
> ⚠️ 스킬은 무료·Pro·Max·Team·Enterprise **요금제**에서 사용 가능하며 **코드 실행(파일 생성) 기능이 켜져 있어야** 합니다. 대화 창 하나에서 채팅·리서치·문서 작업이 함께 처리되는 최신 클로드 **모델**(Haiku 4.5·Sonnet 5·Opus 5.5·Fable 5.1 — API 기준 100만 토큰당 입력 $1~10·출력 $5~50) 어떤 것을 쓰든 스킬 사용법은 동일합니다. 2026년 9월 기준.

## 0. 왜 스킬인가

좋은 프롬프트·맥락·자동화를 만들었지만 매번 다시 불러오는 건 비효율입니다. **스킬(Skill)**은 반복 절차를 클로드가 알아서 적용하는 **재사용 자산**으로 만듭니다. 중급의 "스킬=반복 절차 / 프로젝트=누적 맥락"을 이제 직접 제작합니다.

## 1. 스킬의 구조 (코딩 없이)

스킬은 폴더 하나이고, 핵심은 **`skill.md`** 파일 하나입니다. 파일 맨 위에 `---`로 감싼 메타데이터(YAML), 그 아래에 본문(지시) — 이 순서·형식을 그대로 지켜야 클로드가 스킬로 인식합니다.

```markdown
---
name: 우리 브랜드 가이드
description: 외부용 문서·발표자료에 우리 브랜드 톤·색·로고 규칙을 적용. 콘텐츠 제작 시 사용.
---

## Overview
이 스킬은 ___를 위해 ___할 때 적용한다.

## 규칙
- 톤: 정중한 존댓말 ...
- 색: Primary #...
- 금지: ...
```

- **name(64자 이내)**: 사람이 알아볼 이름.
- **description(200자 이내)**: 가장 중요. 클로드가 **언제 이 스킬을 쓸지** 판단하는 기준. "무엇을 + 언제"를 구체적으로.
- **본문**: `---` 아래에 실제 지시·규칙·예시(자유 형식 마크다운).

> 핵심: description이 곧 '자동 호출 스위치'. 모호하면 안 불리고, 구체적이면 알맞게 불립니다.

## 2. 리소스와 스크립트 (선택)

- 리소스 파일: 내용이 많으면 `REFERENCE.md` 같은 보조 파일을 두고 skill.md에서 언급(필요할 때만 열림).
- 스크립트: 실행 코드도 붙일 수 있지만, **비개발자는 마크다운 지시만으로 시작** 권장. 필요해지면 확장.

## 3. 패키징·업로드·테스트

1. 폴더 이름을 스킬 이름과 일치.
2. 폴더를 **ZIP**으로 압축(폴더가 ZIP 최상위).
3. **Customize > Skills**에서 업로드·활성화.
4. 테스트: 불려야 할 프롬프트로 시험 → 실제로 쓰는지 확인 → 안 쓰면 **description을 다듬어** 반복.

> 1번 페이지의 '평가·반복 개선'을 스킬에 적용하는 겁니다.

## 4. 스킬 설계 베스트 프랙티스

- 한 스킬 = 한 워크플로우(만능 스킬보다 작고 집중된 스킬 여러 개).
- 명확한 description.
- 단순하게 시작, 예시 추가, 점차 확장.
- 조합성: 스킬끼리 직접 호출은 못 하지만 클로드가 여러 스킬을 자동으로 함께 쓴다 — 이게 가장 강력.
- 개방 표준(agentskills.io)을 따르면 다른 플랫폼에서도 동작.

## 5. 플러그인 — 스킬·커넥터 패키징

**플러그인(Plugin)**은 **MCP 커넥터, 스킬, 또는 둘 다**를 역할·팀·회사에 맞게 한 패키지로 묶은 것(Claude Code에서는 서브에이전트도 함께 묶을 수 있습니다). `/` 또는 `+` 버튼 → 플러그인 확인 → Install. Anthropic이 제공하는 역할별 플러그인(영업·제품 등)이 있고, **클로드 마켓플레이스**에서 다른 개발자가 만든 플러그인을 찾아 쓸 수도 있습니다. 개발자용 제출 포털도 열려 있어, 내가 만든 스킬·커넥터 묶음을 심사받아 마켓플레이스에 올릴 수도 있습니다.

## 6. 팀 표준화·거버넌스

- 조직 스킬 프로비저닝(Team·Enterprise): 잘 만든 스킬을 조직 전체에 배포해 품질을 균일하게.
- 조직 인스트럭션: 회사 공통 규칙을 한 번 정해 모든 작업에 적용.
- 공유 맥락도 함께 표준화: 프로젝트(중급 3편)도 폴더 나열형에서 대화형으로 개편이 시작됐습니다(현재 일부 Claude Code Pro·Max 사용자 대상 베타 — 기존 프로젝트는 그대로 동작). 개편판에서는 여러 스레드가 같은 맥락·같은 스킬을 공유하며 일합니다. 스킬은 "어떻게 할지", 프로젝트는 "무엇을 누적할지" — 팀 표준화는 이 둘을 함께 맞추는 일입니다.
- 보안: 스킬에 **민감정보(비밀번호·키) 금지**, 다운로드한 스킬은 **활성화 전 검토**, 외부 접근은 적절한 커넥터로.

## 7. 케이스 + 미션 ✍️

**케이스**: 매번 반복하던 '카드뉴스 텍스트 만들기' 절차를 skill.md로 작성 → ZIP → 업로드 → "이번 주제로 카드뉴스 텍스트" 한마디에 자동 적용되는지 테스트 → description 다듬음.

**미션 1**: 반복 절차 하나를 name / description(언제 쓰는지) / 본문 3~5줄 / 사용 시점으로 작성.

**미션 2**: 두 스킬이 함께 쓰이는 상황 하나.

**미션 3**: 내 역할에 맞는 플러그인이 묶을 스킬·커넥터 정리.

> 한 줄 정리: 고급 스킬은 **코딩 없이 skill.md로 제작(description이 핵심)·패키징·테스트·반복·플러그인 묶음·팀 표준화**입니다. 노하우를 자산으로.
