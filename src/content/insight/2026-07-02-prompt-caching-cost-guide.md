챗봇을 만들든 에이전트를 돌리든, LLM API를 반복 호출하는 서비스에는 매 요청마다 똑같이 딸려 가는 덩어리가 있다. 수천 토큰짜리 시스템 프롬프트, 문서, 예시, 도구 정의 같은 것들이다. 이 앞부분은 요청마다 거의 바뀌지 않는데도, 캐싱을 켜지 않으면 매번 전액을 다시 낸다.

Anthropic 공식 문서는 이 앞부분을 캐시에서 다시 읽을 때 **기본 입력가의 0.1배**만 청구한다고 명시한다. 즉 캐시된 입력 토큰은 **90% 할인**이다(Anthropic Claude Docs, 상시). OpenAI 문서도 프롬프트 캐싱으로 **입력 토큰 비용을 최대 90%, 지연을 최대 80%까지** 줄일 수 있다고 적는다(OpenAI Prompt Caching Docs, 상시). 두 벤더가 독립적으로 같은 수치를 말한다는 점이 이 기법의 실효성을 보여준다.

## 캐싱은 "앞부분이 같으면 싸진다"는 원리다

프롬프트 캐싱은 요청의 **접두부(prefix)**가 이전 요청과 동일하면, 그 부분의 연산 결과를 재사용해 비용과 시간을 줄이는 방식이다. 그래서 설계 원칙은 단순하다. **바뀌지 않는 것을 앞에, 매번 바뀌는 것을 뒤에** 둔다. 시스템 프롬프트·문서·도구 정의는 앞쪽 고정 블록으로, 사용자의 이번 질문은 맨 뒤로 보낸다.

벤더별로 켜는 방식이 다르다.

- **OpenAI**: 자동이다. 코드 변경 없이 gpt-4o 이후 모델에 적용되고, **1,024 토큰 이상** 프롬프트에 작동한다. 캐시 활성화 자체에 추가 요금은 없다(OpenAI Prompt Caching Docs, 상시).
- **Google Gemini**: 암시적(implicit) 캐싱이 Gemini 2.5 이상 모델에서 기본 활성화되며, 캐시 히트 시 비용 절감이 자동 반영된다. 최소 토큰은 Gemini 2.5 Flash·Pro가 2,048, Gemini 3.5 Flash·3.1 Pro Preview가 4,096이다(Google Gemini API Docs, 상시).
- **Anthropic**: 명시적으로 켜야 한다. 요청 최상위에 `cache_control: {"type": "ephemeral"}` 한 줄을 넣는 자동 캐싱 방식이 있고, 이러면 마지막 캐시 가능 블록에 브레이크포인트가 자동으로 붙어 대화가 길어질수록 앞으로 이동한다(Anthropic Claude Docs, 상시).

Anthropic은 대신 **쓰기 프리미엄**이 있다. 캐시에 처음 쓸 때 5분짜리는 기본 입력가의 **1.25배**, 1시간짜리는 **2배**를 낸다. 읽을 때 0.1배로 회수하는 구조라, 같은 접두부를 여러 번 재사용할수록 이득이 커진다. 기본 캐시 수명(TTL)은 5분이고, 캐시가 쓰일 때마다 추가 비용 없이 갱신된다(Anthropic Claude Docs, 상시).

## 최소 토큰 기준을 넘겨야 캐시가 잡힌다

놓치기 쉬운 함정이 최소 토큰 기준이다. 접두부가 이 값보다 짧으면 `cache_control`을 붙여도 캐싱되지 않고, **에러도 나지 않은 채 그냥 정가로 처리**된다. Anthropic 문서 기준 Claude Opus 4.8·Sonnet 5·Sonnet 4.6·4.5는 **1,024 토큰**, Haiku 4.5와 Opus 4.6·4.5는 **4,096 토큰**이 최소값이다(Anthropic Claude Docs, 상시). "캐싱을 켰는데 청구서가 그대로"라면 접두부가 기준 미달인 경우가 많다.

## 대화가 길어지면 캐싱만으로 부족하다 — 컨텍스트 편집

에이전트처럼 도구 호출이 쌓이는 워크로드는 대화 히스토리 자체가 계속 커진다. 캐싱이 앞부분을 싸게 해줘도, 뒤로 갈수록 불어난 도구 결과가 창(context window)을 잠식하고 모델 집중도를 떨어뜨린다.

Anthropic의 **컨텍스트 편집(context editing)**은 이 지점을 서버 측에서 손본다. 베타 헤더 `context-management-2025-06-27`로 켜며, 대화가 설정된 임계값을 넘으면 오래된 내용을 선별적으로 비운다. 클라이언트는 원본 히스토리를 그대로 들고 있고, 모델에게 가는 프롬프트만 정리되는 구조다. 도구 결과 비우기(`clear_tool_uses_20250919`)의 기본값은 입력 **10만 토큰**에서 발동, 최근 도구 사용 **3개**를 유지한다. 비워지기 전에 중요한 내용을 메모리 툴(`memory_20250818`)에 저장하도록 경고도 준다(Anthropic Claude Docs, 상시).

## 한계와 주의점

- **할인은 재사용을 전제로 한다.** 매 요청 접두부가 다르면 캐시 히트가 안 나고, Anthropic에서는 쓰기 프리미엄만 물 수도 있다. 캐싱 설계 전에 "정말 앞부분이 반복되는가"부터 확인해야 한다.
- **캐시 수명은 짧다.** OpenAI는 비활성 5~10분(최대 1시간, 신모델은 확장 시 최대 24시간), Anthropic 기본은 5분이다(각 벤더 공식 문서, 상시). 트래픽이 뜸하면 캐시가 만료돼 절감 효과가 줄어든다.
- **격리 정책을 확인하라.** Anthropic은 2026년 2월 5일부터 Claude API·AWS Claude Platform·Microsoft Foundry에서 캐시를 **워크스페이스 단위**로 격리한다. 워크스페이스가 다르면 캐시를 공유하지 않는다(Anthropic Claude Docs, 2026-02-05).
- **수치를 단정하지 마라.** Gemini 공식 캐싱 문서에는 할인율이 구체적으로 명시돼 있지 않다. "암시적 캐싱으로 절감이 자동 반영된다"까지가 확인 가능한 사실이다.

## 한 줄 정리

프롬프트 캐싱은 "앞부분이 같으면 싸진다"는 단순한 원리이고, 벤더 공식 문서가 입력 비용 최대 90% 절감을 명시한다. 반복되는 접두부를 앞에 고정하고, 최소 토큰 기준을 넘기고, 긴 대화는 컨텍스트 편집으로 다듬는 것 — 이 세 가지가 LLM API 청구서를 실제로 줄이는 기본기다.
