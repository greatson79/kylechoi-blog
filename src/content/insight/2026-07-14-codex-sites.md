프롬프트 한 줄로 사내 대시보드를 만들고, 그 자리에서 프로덕션 URL까지 받을 수 있다면 어떨까. OpenAI가 Codex에 붙인 **Sites 플러그인**이 그 이야기다. 이번 주는 이 기능이 정확히 무엇이고, 어떻게 쓰는지를 공식 문서와 실측 분석 기준으로 정리한다.

## 1. 먼저 시점을 정리합니다 — Sites는 GPT-5.6 때문에 생긴 기능이 아닙니다

검증 과정에서 확인한 사실을 먼저 짚습니다. Sites는 **2026년 6월 2일**, OpenAI의 'Intelligence at Work' 행사에서 Annotations·역할별 비즈니스 플러그인 6종과 함께 먼저 공개됐습니다(6월 4일에는 팀(Team) 플랜에도 출시). GPT-5.6이 Codex에 반영된 건 그보다 늦은 **7월 9일**입니다 — 이때 공식 changelog에는 "Made Computer Use faster with GPT-5.6" 같은 항목은 있지만, Sites 전용 업데이트 항목은 확인되지 않습니다.

정리하면 이렇습니다 — **Sites는 GPT-5.6 이전(6월)에 이미 나와 있던 기능**이고, GPT-5.6·ChatGPT 데스크톱 통합(7월 9일)은 Codex의 모델 세대가 한 단계 올라간 별개의 사건입니다. 이 글의 제목을 "GPT-5.6 세대 Codex에서 쓸 수 있는 Sites"라고 쓴 이유입니다 — "GPT-5.6이 Sites를 새로 추가했다"는 인과관계로 읽히지 않도록 모델과 기능을 분리해서 소개합니다.

## 2. Codex "Sites"는 정확히 무엇인가

Sites는 **Codex 앱 안에 내장된 플러그인**입니다. 기존에는 "AI가 파일을 생성한다 → 사람이 다운로드한다 → 어딘가에 직접 배포한다"는 3단계를 거쳐야 했다면, Sites는 이 과정을 Codex 앱 안의 **일급(first-class) 배포 파이프라인**으로 대체합니다.

> "Sites is a Codex plugin that replaces the previous workflow of 'generate a file, download it, deploy somewhere else' with a first-class deployment pipeline inside the Codex app."

OpenAI는 발표문에서 이 기능을 더 폭넓게 이렇게도 소개했습니다.

> "Sites are a new kind of canvas for your ideas. Codex can take your ideas, analysis, and plans and turn them [into] dashboards, planners, review workspaces, project boards, galleries, and lightweight tools."

핵심은 두 문장을 합쳐서 봐야 정확합니다 — Codex가 사용자를 대신해 사이트를 **생성·저장·배포·검사(create, save, deploy, inspect)**하고, 그 결과가 곧바로 실행 가능한 프로덕션 URL이 된다는 것입니다. 별도의 배포 도구나 개발 리소스 요청 없이 대화 안에서 이 전체 과정이 끝납니다.

**만들 수 있는 것 예시**: 재무 시나리오 플래너, 운영팀 프로젝트 요청 대시보드, 작업 추적 도구, 경량 CRUD 애플리케이션, 내부 포털·리포트, 런치 캘린더, 프로토타입, 간단한 게임 등입니다.

> **따라 해보기 전에 먼저 확인하세요**
> Codex Sites는 **ChatGPT Business·Enterprise 워크스페이스 전용 프리뷰 기능**입니다. **개인 Plus·Pro나 무료 플랜에서는 이 시점 기준 쓸 수 없습니다.** 팀(Team) 플랜은 6월 4일부터 열렸고, 그 외 플랜은 순차 확대 중입니다. 회사 워크스페이스 계정이 없다면 아래 사용법을 그대로 따라 해도 화면에 `@Sites` 자체가 뜨지 않을 수 있습니다 — 먼저 소속 워크스페이스가 Business·Enterprise·Team 플랜인지, 관리자가 Sites를 켜뒀는지부터 확인하고 넘어가세요.

## 3. 실전 사용법 — 명령과 승인 게이트

![손으로 그린 구상이, 대화 한 줄 뒤에는 실제로 돌아가는 화면이 된다.](/images/ai-trend/body_codex-sites_0714.jpg)

먼저 분명히 해둘 것이 있습니다. **Sites는 CLI 명령이 아닙니다.** 터미널에서 쓰는 Codex CLI 공식 레퍼런스를 직접 확인했지만 `codex sites` 같은 서브커맨드는 존재하지 않습니다. Sites는 **Codex 에이전트(앱) 안의 플러그인**으로만 호출합니다.

**① `@Sites`로 부른다**
Codex 대화창에서 `@Sites`를 붙여 자연어로 요구사항을 씁니다. 실제 예시 명령은 이렇습니다.

```
@Sites Build a project request dashboard for the operations team.
```

담당자·상태·마감일 같은 컬럼, 로그인 요구 여부, 필터링 방식까지 이 한 문장(또는 이어지는 대화)에서 구체적으로 설명할수록 결과가 정확해집니다.

**② Codex가 생성하고, 배포 가능한 버전을 저장한다**
Codex가 사이트 출력을 만들고, 검토용으로 배포 가능한 버전을 저장합니다. 이 시점에는 아직 외부에 공개되지 않습니다.

**③ 승인 게이트를 통과한다**
저장된 버전을 사용자가 검토한 뒤 **승인 또는 거부**합니다. 이 승인 단계가 있다는 점이 중요합니다 — Codex가 만들었다고 바로 나가는 게 아니라, 사람이 한 번 확인하는 절차가 파이프라인에 내장돼 있습니다.

**④ 승인하면 곧바로 프로덕션 URL이 된다**
승인 즉시 별도의 "발행" 버튼 없이 반환된 URL이 그대로 프로덕션 배포입니다. 이 URL을 워크스페이스 멤버와 공유합니다.

**설정 파일**: Sites가 만든 프로젝트에는 `.openai/hosting.json` 설정 파일이 생성됩니다.

```json
{ "project_id": "<auto-generated-id>", "d1": "DB", "r2": null }
```

데이터를 저장해야 하는 도구라면 상태 지속용으로 **D1**(SQLite 호환 관계형 DB), 파일·이미지 저장용으로 **R2**(S3 호환 오브젝트 스토리지)를 씁니다. 호스팅 자체는 **Cloudflare 엣지 인프라** 위에서 OpenAI가 대신 운영합니다.

## 4. 접근 범위·플랜 제약 — 실전팁의 핵심

여기가 실무에서 가장 먼저 부딪히는 지점입니다.

- **플랜**: ChatGPT **Business·Enterprise** 워크스페이스 대상 프리뷰입니다. **개인·무료 계정에서는 이 시점 기준 사용할 수 없습니다.** 팀(Team) 플랜은 6월 4일부터 출시됐고, 그 외 플랜은 순차 확대 중입니다.
- **접근 제어 3모드**: `admins_only`(소유자·관리자만) / `workspace_all`(워크스페이스 전체) / `custom`(지정 사용자·그룹). 공통적으로 **뷰어는 해당 OpenAI 워크스페이스의 활성 멤버여야 한다**는 제약이 실측 분석에서 확인됩니다.
- **미지원 항목**: 커스텀 도메인 연결, 코드 내보내기·셀프호스팅, 외부(비워크스페이스) 공유는 현재 지원하지 않습니다.

> **교차검증 메모**: OpenAI 공식 문서(learn.chatgpt.com/docs/sites)는 공유 범위를 "초대전용 / 워크스페이스 전체 / 링크를 아는 사람 누구나"로 설명하고 있어, 위 3모드 분석(외부 뷰어 전면 미지원)과 문구상 온도차가 있습니다. "링크 공유"가 실제로는 여전히 워크스페이스 로그인을 요구하는 것인지는 출처 간 표현이 갈려 이 글에서는 단정하지 않습니다 — 대외 공개용으로 쓸 계획이라면 워크스페이스 관리자에게 현재 설정을 직접 확인하는 걸 권합니다.

## 5. 실무 활용 시나리오 5가지

1. **운영팀 프로젝트 요청 대시보드** — `@Sites Build a project request dashboard for the operations team.` 요청 접수부터 상태 추적까지 사내 URL 하나로.
2. **재무 시나리오 플래너** — 가정값을 입력하면 시나리오를 비교해주는 인터랙티브 웹앱. D1에 상태를 저장.
3. **경량 내부 CRUD 툴** — 재고·자산·명단 관리 같은 소규모 도구를 코드 배포 없이.
4. **런치 캘린더·프로젝트 트래커** — 팀 일정·마일스톤을 공유하는 포털.
5. **프로토타입 즉시 배포** — 아이디어를 인터랙티브 프로토타입으로 만들어 워크스페이스 안에서 바로 검토.

**실전팁의 진짜 포인트**는 "만들고 → 다운받고 → 어딘가에 올리는" 3단계가 사라지고, `@Sites` 한 번의 지시로 생성부터 프로덕션 URL까지 이어진다는 것입니다. 다만 지금은 **사내(워크스페이스) 공유 전용**에 가깝다는 걸 전제로 써야 합니다 — 대외 공개 사이트 제작 도구로 바로 대체하기는 이릅니다.

## 6. 마무리

정식 개발 리소스를 배정받기 전에 "이게 실제로 쓸모가 있는 도구인지" 프로토타입으로 먼저 검증하고 싶을 때, Sites는 `@Sites` 한 줄로 그 간극을 메워줍니다. 다만 지금은 Business·Enterprise 워크스페이스 프리뷰 단계이고, 개인 계정에서는 아직 쓸 수 없으며, 대외 공개보다는 사내 도구에 맞춰져 있다는 제약을 함께 기억해두는 게 좋습니다. 그리고 이 기능은 GPT-5.6이 만든 게 아니라 그보다 한 달 앞서 나온 기능이라는 시점도 함께요.
